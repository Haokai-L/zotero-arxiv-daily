# R4-2 — audited incremental CCF discovery (no emails)

This incremental workflow is intentionally **not scheduled**. It runs once on a
change to its own source files on `feature/ccf-a-daily`; later a manual dispatch
or a separately approved scheduler can run it. It never sends mail or calls
DeepSeek. It never touches `main`, Zotero, or credentials except reading the
existing OpenAlex API secret.

## What is persistent?

- `data/ccf_candidate_state.json` (generated by GitHub Actions on the feature
  branch): bounded, preliminary paper metadata, DOI or official URL key,
  first/last seen, source evidence and provenance. Initial seed is the
  successful R3-4a audit if its artifact remains accessible. The snapshot is
  optional; without it the service starts with newly discovered papers.
- `data/ccf_sent_history.json` (starts empty): **read-only** from discovery;
  only a future *confirmed successful email delivery* should add an identifier.
  A paper shown in a recommendation preview is **not** considered sent.

All sources come from the six journal OpenAlex source IDs plus ten explicitly
mapped 2026 conference sources. NSDI, USENIX Security and NDSS use their official
2026 paper listings. CRYPTO/EUROCRYPT chapters must match one of the explicitly
verified 2026 Springer proceedings volume DOIs, rather than arbitrary LNCS.
ACM and IEEE Crossref entries must match main-conference container, publisher,
DOI prefix, year and type. Rejected and uncertain records never enter the
candidate state as certified publications.

## Incremental behavior and limitations

For journals the collector re-queries overlapping 60-day publication windows;
for conference Crossref records, first run uses a bounded current-year query
and later runs query the last 45 days of Crossref *indexing* activity. Official
conference listings are rechecked, then deduplicated by DOI or official URL.

The initial run **does not claim full 2024–2026 coverage**. The 2026 ACM and
IEEE conference matching titles still depend on external metadata deposit
quality; any source with no accepted matches is explicitly marked
`NEEDS_REVIEW_NO_MATCH`. A `BOUNDED_PAGINATION` source indicates more provider
records exist beyond the configured page cap, not exhaustive coverage. Missing
provider responses prevent state persistence and are reported in the artifact.
The source map intentionally fails when the year changes; add a verified
next-year venue map before enabling a true production schedule.

## Follow-up needed before any automatic daily email

1. Inspect source audit and resolve any 2026 conference proceedings aliases,
   partial pagination or missing official listing issues.
2. Wire the durable `unsent_candidates.csv` into R4-1 enrichment and Zotero
   scorer, not the expiring R3-4a static snapshot.
3. Complete official paper verification, persist positive and negative
   recommendation decisions, and implement transactionally recorded SMTP
   delivery before modifying the `sent_keys` history.
4. Explicitly authorize a scheduled check and scheduled emails separately.
